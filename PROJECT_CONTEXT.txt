0. TL;DR (read this if nothing else)

* Mr File Fixit is a FREE, FULLY OFFLINE ANDROID APP written in Kotlin + Jetpack Compose
  (Material 3). It is NOT Flutter and NOT React Native, even though some of the user's prompts
  were written as if it were. It is NOT a web app (the repo used to hold a React/Vercel web app;

  Package / applicationId: com.mrfilefixit.app (debug builds: com.mrfilefixit.app.debug).
  versionCode 2, versionName "1.0.0" (not bumped per beta tag).

  fixer with live pass/fail checker), PDF tools (19 tools incl. Word/PowerPoint/Excel <-> PDF),
  Image tools (Resize, Crop, Rotate, Compress, Convert incl. to PDF, Edit, Enhance, Remove

=====================================================================
1. PRODUCT SUMMARY
=====================================================================

Target users: Indian government-exam and entrance-exam applicants (and general users) who must
upload photos, signatures, thumb impressions, handwritten declarations and certificate PDFs within
strict pixel/KB/format limits, plus everyday PDF/image/office/resume tasks.

Core promises (shown in Settings > Privacy and docs/PLAY_STORE.md privacy policy):
  1. 100% on-device processing (image, PDF, office conversion, OCR, resume).
  2. Nothing is sent anywhere: no ads, analytics, servers, accounts. Exception disclosed honestly:
     Google ML Kit (document scanner + text recognition) may send anonymous usage statistics via
     com.google.android.datatransport; never images, text or file names.
  3. Temporary files live in app-private cache (cache/jobs/<uuid>/) and are wiped when leaving a
     tool / ViewModel cleared, on failure/cancel, and by a start-up sweep of dirs older than 6 h.
  4. Metadata (EXIF location, camera, etc.) is stripped on export.
  5. No storage permissions: Photo Picker / SAF (OpenDocument, CreateDocument) only; sharing via
     FileProvider with a single read-grant URI.

Languages: English and Hindi (values/ and values-hi/ strings in every UI module; lint makes
MissingTranslation and HardcodedText errors). Per-app language via locales_config.xml (en, hi).
App name "Mr File Fixit" is not translated; home shows "Mr File" + accent-coloured "Fixit".

Theme: Material 3, System / Light / Dark, optional dynamic colour ("Use wallpaper colours").
Adaptive layout: NavigationSuiteScaffold = bottom bar on phones, navigation rail on tablets and
foldables; list-detail panes for exam picker and PDF tool picker.

3.1 Exam forms (:feature-exam)
------------------------------
* Data: feature-exam/src/main/assets/exam_rules.json, schemaVersion 2, validated in CI against
  docs/exam-rules.schema.json. Parsed lazily by AssetExamRulesRepository / ExamRulesParser into
  domain ExamProfile. Golden test: feature-exam/src/test/resources/golden/exam_rules.golden.txt
  (update it when the JSON changes; run ./gradlew :feature-exam:testDebugUnitTest).
* Picker: search bar ("Search exams (e.g. SSC, UPSC, GATE)"), category pills (All + categories that
  have profiles, in enum order), exam count, cards with conducting body, verification badge and
  quick chips "Photo (20-50 KB)", "Sign (10-20 KB)", "Docs (...)", "+N more uploads". Search is pure
  (ExamCatalog) and matches short name, full name, body, id and category aliases (e.g. "bank").
  Collapsible disclaimer card "Check the official notice" (2 lines + Read more / Show less).
* Detail: tabs Photo / Signature / Other uploads (thumb, declaration, postcard photo) /
  Certificates. Each slot shows requirements (dimensions, KB, format, background, ink, notes),
  lets the user pick a file, crop in a frame matching the required aspect, rotate 90 deg,
  "Fix to fit", then shows "Ready to upload" or "Some checks still fail" with the live checklist
  (Format, File size, Width, Height), Save (SAF) and Share. If an image is below the minimum KB even
  at quality 100, padding bytes are added to the file (picture unchanged) and a note says so.
  Composite "Photo and signature in one image" is supported by schema + domain + UI
  (MergePhotoSignatureUseCase) but NO bundled profile currently defines a composite.
  "Prepare Files for This Exam" opens Image tools > Resize with the exam's presets.
  Certificates tab lists PDF/JPG uploads with KB windows and a "Compress PDF to fit" button.
* Pipeline (PrepareExamDocumentUseCase): input limits -> read info -> rotate -> crop (user or
  centred to target aspect) -> resize FILL to targetPx -> encode JPEG with KB targeting
  (QualitySearch, max 8 encodes, up to 3 downscale steps, padding allowed for JPEG) -> SpecChecker.
* KB safety: DocumentSpec.targetBytes aims at [minKb*1024 + 256 B, maxKb*1000 - 256 B] so the file
  passes whether a portal counts a KB as 1000 or 1024 bytes (falls back to the declared range when
  that window is empty).
* Disclaimer text (core-ui strings): "These sizes are collected from public guides and official
  pages, but they are not official rules and they change every year. Always verify ... against the
  official notification of your exam before you submit." Shown on every exam screen. Badge:
  "Community sourced" or "Checked on official page, <date>".

3.2 PDF tools (:feature-pdf), 19 tools in 4 groups (PdfTool enum)
-----------------------------------------------------------------
ORGANIZE: Merge PDFs (reorderable list, >= 2 files), Split PDF (Custom range / Every N pages /
          Single pages, with a preview of resulting files), Extract pages, Reorder pages,
          Rotate pages, Delete pages.
CONVERT:  Images to PDF (page size A4/Letter/Legal/Same as image in a 2x2 grid, orientation
          Auto/Portrait/Landscape, margins None/Small 5 mm/Big 10 mm, reorderable thumbnails),
          PDF to JPG (dpi slider), Word to PDF, PDF to Word, PowerPoint to PDF, PDF to PowerPoint,
          Excel to PDF, PDF to Excel (XLSX or CSV), plus a tile "Text recognition (OCR)" that opens
          the OCR screen.
OPTIMIZE: Compress PDF (Light 150 dpi/q75, Medium 120 dpi/q60, Strong 96 dpi/q45, optional
          grayscale), Add watermark (text, opacity, diagonal), Add page numbers (position bottom
          centre/bottom right/top right, styles "n", "n / total", "Page n of total").
SECURITY: Add password, Remove password (known password only).
Engine: pdfbox-android (com.tom-roush:pdfbox-android 2.0.27.0) for structure/encryption/stamping;
platform PdfRenderer for rendering, one page at a time.
PDF compressor (core-processing/.../pdf/PdfCompressor.kt) after the PR #19 fix (it used to
rasterize everything and could make files BIGGER, e.g. 558 KB -> 1000 KB):
  1. Structural pass: downsample/re-encode embedded images above the level's dpi as JPEG, only if
     the new stream is smaller; Flate-compress raw content streams; drop metadata, thumbnails,
     piece info. Images with a fully opaque soft mask are re-encoded (flattened on white); real
     transparency is kept.
  2. Strong level only, only if step 1 did not shrink: rasterize pages to JPEG one at a time.
  3. Guardrail: smallest candidate strictly smaller than the source wins; otherwise fail with
     AppError.AlreadyOptimized ("already as small as it can get"), nothing written.
  Rules live in pure PdfCompressionPolicy (unit tested); PdfCompressorTest runs on the emulator.
Passwords: CharArray only, zero-filled after the job (PdfOperation.wipeSecrets), never stored,
never in SavedStateHandle, toString redacted.
Watermark / page-number stamps: Latin letters and numbers only (UI says so); other scripts are not
supported in stamps yet.
Encrypted PDFs: other tools refuse with "This PDF is password-protected. Unlock it first."

3.3 Office conversions (:core-office + core-processing/convert), see docs/CONVERSIONS.md
-----------------------------------------------------------------------------------------
Pure Kotlin, NO third-party office library (no Apache POI). Reads DOCX/PPTX/XLSX (strict XML pull
parser rejecting DTDs), legacy DOC/PPT/XLS via a bounded Compound File reader, CSV. Writes DOCX,
PPTX, XLSX. Layout to PDF uses Android StaticLayout on android.graphics.pdf.PdfDocument (fonts map
to Android system families incl. Hindi/Indic, Arabic, Cyrillic, CJK). PDF -> office reads glyph
positions with PDFBox (pdftext/: lines -> paragraphs, headings, lists, two-column, tables, slides).
  * Word -> PDF keeps text styles, headings, lists, tables (merged cells keep text but grid lines
    still show), inline pictures, page breaks, page size/margins.
  * PPT -> PDF: one page per slide at slide size; .ppt gives titles + body text on plain slides.
  * Excel -> PDF: values as Excel shows them, bold, column widths; bold first row repeats; >= 7
    columns landscape; > 10 columns split into bands of ten (A-J, K-T ...).
  * PDF -> Word: paragraphs, headings, real list items, de-hyphenation, two-column reading,
    pictures kept.
  * PDF -> PowerPoint: page picture WITHOUT its text as background + every text line as an editable
    text box at the same position.
  * PDF -> Excel: cells by wide gaps, columns aligned per page (columns come from multi-cell rows so
    headings do not merge columns), numbers with separators/currency (Rs symbol $ EUR GBP JPY)/
    percent/accounting negatives become numbers. XLSX one sheet per page, or CSV all pages.
Known limits: no charts, SmartArt, WordArt, equations, comments, tracked changes, headers/footers,
footnotes, floating shapes/text boxes, animations; EMF/WMF/TIFF pictures dropped; fonts replaced
by nearest Android family; password-protected Office files rejected (DocumentProtected); scanned
PDFs have no text (NoTextFound for Excel; Word gets page pictures; PPT slides not editable);
text inside form XObjects appears twice in PDF->PPT; PDF->Excel does not detect ruled lines,
merged or multi-line cells.
Safety caps (OfficeLimits): ZIP <= 4000 entries, 64 MiB per entry, 256 MiB total; 500 slides,
100 000 rows, 1 000 columns, 200 000 paragraphs, 2 000 output pages -> DocumentTooComplex.
Macros, OLE objects and external links never run/followed.

3.4 Image tools (:feature-image), tabs (ImageTool enum) - see docs/IMAGE_TOOLS.md
----------------------------------------------------------------------------------
RESIZE (width/height with "Keep aspect ratio" link that recalculates the other side; presets:
        linked exam's uploads first, then Passport 413x531, then SSC CGL photo, UPSC CSE signature,
        IBPS PO photo; optional target KB), CROP (single image only; Original/1:1/4:3/3:4/16:9,
        bounded canvas), ROTATE, COMPRESS (quality or target KB), CONVERT (JPG/PNG/WebP/HEIC out;
        HEIC/WebP/PNG/JPG in; HEIC output needs a hardware HEVC encoder and API 28+; "PDF" puts all
        picked images in one PDF, a page per image at its own size), EDIT, ENHANCE, STRIP_EXIF
        ("Remove metadata": lossless for JPEG/PNG, keeps JFIF + ICC only), plus a last tab
        "Text (OCR)" that opens the OCR screen.
EDIT: Look (Original / Black and white / Document = the Scan clean-paper filter), brightness,
      contrast, saturation (-100..100, one 4x5 colour matrix), one line of text (top/middle/bottom,
      6% of height, outline for light text, "Dark text" option), and the exam "Name and date bar"
      (white or black band across the bottom fifth, up to two centred lines name + date, today's
      date pre-filled; option "Keep the file between 20 and 50 KB" -> JPEG targeted to 20 KiB ..
      50 kB with padding/downscale allowed).
ENHANCE: 2x or 4x upscale in 2x bilinear steps + unsharp mask (sharpness slider, default 0.6),
      done in 256-row bands; long side capped at 3072 px. Classic upscaling, NOT AI. No
      super-resolution model is bundled and the app cannot download one.
Effects order: geometry (rotate, crop, resize) -> upscale -> document filter -> colour matrix ->
name/date bar -> text. ImageEffects is serializable so background batches carry it.
Batches: everything free and unlimited. Up to BatchPolicy.INLINE_LIMIT = 10 files run in the
ViewModel; more run in WorkManager (BatchImageWorker, expedited, foreground service type
dataSync|mediaProcessing only while running, progress notification, POST_NOTIFICATIONS asked on
Android 13+). Input limit 100 files per job.

3.5 Scan & OCR tab (:feature-scan)
----------------------------------
Two hero cards: "Scan with Camera" (Google ML Kit Document Scanner via Play services,
SCANNER_MODE_FULL, up to 20 pages, JPEG + PDF results) and "Extract Text from Storage" (pick
JPG/PNG/PDF). Privacy footer card. After scanning: copied into cache/jobs/<id>/, "Enhance scan"
filters: Document clean (default), Magic colour, Grayscale, Original. Filters use an illumination
map (max filter + box blur on a small copy, then per-pixel division) = local adaptive equivalent of
Otsu/Sauvola with smooth edges; full resolution, applied row by row; PDF rebuilt from enhanced
pages. Quick inline OCR (Latin/Devanagari/Auto etc.), Copy/Share text, and "Searchable PDF, Word
and more languages" hands pages to the OCR screen.
Perspective correction/edge detection is done by the ML Kit scanner UI itself.

3.6 Text recognition / OCR screen (:feature-ocr) - see docs/OCR.md
------------------------------------------------------------------
Inputs JPG, PNG, WebP, PDF. Engines: Google ML Kit BUNDLED models (no download, offline):
text-recognition (Latin), -devanagari (Hindi, Marathi, Nepali, Sanskrit), -chinese, -japanese,
-korean. Each non-Latin model also reads English. Auto-detect (ScriptDetector, pure JVM): runs all
on page 1; a non-Latin script wins with >= 6 own-script letters and >= 1/4 of the Latin count;
Japanese beats Chinese only with kana; blank first page defers to the next.
NOT supported: Bengali, Tamil, Telugu, Gujarati, Kannada, Malayalam, Arabic, Cyrillic and other
scripts ML Kit lacks (would need e.g. Tesseract + traineddata; no in-app downloader because the
app has no network code). The user's request asked for "all major world languages" - this is the
documented gap.
Outputs: Copy (marked sensitive for Android 13+ clipboard preview), Share text, Searchable PDF
(original pages kept, pages with /Rotate redrawn as JPEG, images become A4-wide pages; invisible
text layer drawn with platform PdfDocument at lowest non-zero alpha and stamped as a form XObject
via PDFBox), Text file (UTF-8), Word, Text-only PDF. Exports in a job folder deleted on next export,
clear/close, or next app start.

3.7 Resume builder (:feature-resume) - see docs/RESUME.md
---------------------------------------------------------
15 templates (ResumeTemplates/TemplateCatalog): Software and IT, Core engineering, Arts (photo),
Marketing, Finance and accounting, Data science and AI, Healthcare (photo), Teaching, Graphic
design (photo), Fresh graduate, Business and management, Legal, Human resources, Operations and
supply chain, Academic CV (photo). Each has default section order, sample text, font and accent;
changing template keeps text and order.
ATS rules: single column, real selectable text, real headings and bullet lists in PDF and DOCX,
name/contact in body (not header/text box), real links, optional photo in a borderless two-cell row
beside the name.
Editing: sections Summary, Experience, Education, Skills, Projects, Certifications, Custom (any
number); rename, hide from export, move up/down, delete; entries movable. Look: font Sans / Serif /
Narrow / Mono, body size 9-13 pt in half points, accent colour, A4 or US Letter. Photo: system
photo picker, 35x45 frame with pinch/drag, cropped and resized to 413x531 px JPEG (fits both
350x450 and 413x531 Indian sizes). Autosave ~0.5 s after last change and on close.
Export: PDF (DocumentPdfWriter, same engine as Word->PDF, previewed in-app) and DOCX (DocxWriter).
The DOCX embeds the draft JSON in a custom XML part so "Open an exported Word file" restores an
editable draft (as a new draft, without the photo). Other DOCX files -> NotAResume error.
Storage: files/resumes/<id>.json and <id>.jpg (app-private, atomic temp+rename, ids validated
[A-Za-z0-9-], photo only from own cache). Backup disabled app-wide.

JVM 17 target, allWarningsAsErrors, -Xjsr305=strict. Compose BOM 2025.12.00, Material 3,

Dependency rule: features depend only on :core-ui and :core-domain; implementations reach the app
only through :app. :core-processing depends on :core-domain and :core-office. :core-office depends

Key patterns:
  * Result<T, AppError> sealed interface everywhere (AppResult<T>). runCatchingApp {} at data-layer
    boundaries; CancellationException always rethrown. AppError carries numbers/enums only, never
    file names; Unexpected(type) keeps only the exception class name.
    AppError cases: FileTooLarge, DimensionsTooLarge, TooManyPages, TooManyFiles, UnsupportedFormat,
    CorruptFile, EmptyFile, PasswordRequired, WrongPassword, InvalidPageSelection,
    TargetSizeUnreachable, FileNotFound, PermissionDenied, StorageFull, OutOfMemory,
    FeatureUnavailable(HEIC_DECODE|HEIC_ENCODE|WEBP_ENCODE|DOCUMENT_SCANNER|OCR|BATCH_WORKER),
    AlreadyOptimized, DocumentProtected, DocumentTooComplex, NoTextFound, NotAResume, Unexpected.
  * JobRunner<T>(viewModelScope): one job at a time, StateFlow<JobState<T>> with Idle,
    Running(progress 0..1 or null), Success, Failed(AppError), Cancelled; cleanup always runs under
    NonCancellable. ProgressReporter.slice/step for multi-step progress. Engines call ensureActive()
    between pages/images.
  * InputLimits (checked before decoding): 50 MiB per file, 64 MP, 16 384 px max side, 1 000 PDF
    pages, 100 files per job. Size checked from SAF metadata and again while streaming.
  * FilenameSanitizer: strips path separators, control and bidi/format chars, "..", reserved
    Windows names, 100-char cap, keeps Unicode (Hindi) letters.
  * Logging: AppLogger contract; TimberLogger logs only in debug; release plants ReleaseTree (no-op);
    R8 strips android.util.Log calls. No crash-reporting SDK.
  * DispatcherProvider injected; decode/encode on default, I/O on io.

5. SECURITY, PRIVACY, PERMISSIONS (docs/SECURITY.md is authoritative)
=====================================================================
* Network isolation: build-logic NetworkIsolation.kt registers verifyNetworkIsolation on EVERY
  module including :app (releaseRuntimeClasspath / runtimeClasspath). Fails on okhttp, retrofit,
  ktor, volley, cronet, com.google.firebase (except firebase-annotations, -components, -encoders,
  -encoders-json, -encoders-proto which ML Kit telemetry pulls in), play-services-ads, UMP, or a
  module manifest declaring INTERNET. com.google.android.datatransport is deliberately allowed
  (ML Kit anonymous telemetry; pending product decision whether to exclude it - needs device test).
  Detekt ForbiddenImport bans java.net.URL/HttpURLConnection/Socket, javax.net.*, okhttp3.* etc.
* Merged manifest DOES contain INTERNET (from ML Kit) - documented in PLAY_STORE.md as only for ML
  Kit model delivery/diagnostics. CI fails if READ/WRITE/MANAGE_EXTERNAL_STORAGE, READ_MEDIA_*,
  AD_ID or com.google.android.gms.ads appear, and requires allowBackup="false".
* App manifest: removes storage permissions with tools:node="remove"; declares FOREGROUND_SERVICE,
  FOREGROUND_SERVICE_DATA_SYNC, FOREGROUND_SERVICE_MEDIA_PROCESSING, POST_NOTIFICATIONS;
  allowBackup=false + backup_rules/data_extraction_rules exclude everything; network_security_config
  cleartext off, system CAs only; heifwriter overrideLibrary (API 28 gated); WorkManager default
  initializer removed (on-demand init with Hilt factory); enableOnBackInvokedCallback.
* Temp files: cache/jobs/<uuid>/ only; deleted on failure/cancel/reset/ViewModel cleared; stale
  (> 6 h) at app start. importToJob accepts only content:// or file:// inside app storage.
* EXIF: every re-encode drops metadata; lossless strip keeps JFIF + ICC; PNG keeps critical +
  colour chunks. PDF compression drops document metadata.
* Lint: TrustAllX509TrustManager ignored only for Bouncy Castle jars (pdfbox encryption dependency).
